## 2. Починить отправку заявки из корзины
Имя и телефон тут не при чём — они проходят проверку. Заявка падает на стороне базы:
в журнале ошибка «new row violates row-level security policy for table "orders"».

Причина: покупателю разрешено **создавать** заявку, но не разрешено её **читать**
(и это правильно — чужие заказы видеть нельзя). При этом код после создания заявки просит
базу вернуть её номер, то есть выполняет чтение — и база отклоняет всю операцию.

Что сделаю:
- Номер заявки буду создавать заранее на сервере и записывать вместе с заявкой, без обратного чтения. То же для позиций заявки.
- Покупатель при сбое увидит понятное сообщение, а не общую ошибку.

## 3. Проверка и завершение
- Пройду оформление заявки в превью: добавить букет → заполнить форму → «Заявка принята».
- Войду новым администратором и проверю разделы «Заявки», «Товары», «Сотрудники».
- Убедюсь, что проект собирается без ошибок.

## Технически
- Аккаунт создаётся через Auth Admin API (`email_confirm: true`), роль — запись в `user_roles`; старый пользователь удаляется, профиль и роль уходят каскадом.
- `src/lib/orders.functions.ts`: `crypto.randomUUID()` для `orders.id`, вставка без `.select().single()`.
- Политики RLS не меняю: публичное создание заявок остаётся, чтение — только у сотрудников.
