# Администратор и сотрудник + починка отправки заявки

## 1. Аккаунты сотрудников
- Создам администратора `admin@admin.com` (пароль `password1234567`), почта подтверждена сразу.
- Создам сотрудника `sotr1@admin.com` (пароль `sotr12345_1`) с правами обычного сотрудника.
- Полностью удалю прежний аккаунт `kab210975@gmail.com` вместе с его правами и профилем.
- Вход — страница «Вход для сотрудников» (ссылка есть в футере сайта).

## 2. Разделение прав
| Что можно | Сотрудник | Администратор |
| --- | --- | --- |
| Видеть заявки покупателей | да | да |
| Менять статус заявки и писать заметку | да | да |
| Удалять заявки | нет | да |
| Добавлять, менять и удалять товары | да | да |
| Скрывать/показывать товар | да | да |
| Управлять сотрудниками и правами | нет | да |

Сотрудник видит разделы «Заявки» и «Товары»; раздел «Сотрудники» и удаление заявок остаются
за администратором. Права проверяются и в базе, не только в интерфейсе.

## 3. Починить отправку заявки из корзины
Имя и телефон тут не при чём. Заявка падает на стороне базы: «new row violates row-level
security policy for table "orders"». Причина: покупателю разрешено **создавать** заявку, но не
**читать** её (и это правильно), а код после создания просит базу вернуть номер заявки —
то есть выполняет чтение, и вся операция отклоняется.

Что сделаю: номер заявки буду формировать заранее на сервере и записывать вместе с заявкой,
без обратного чтения. При сбое покупатель увидит понятное сообщение.

## 4. Проверка
- Оформлю заявку в превью: букет → форма → «Заявка принята».
- Войду администратором и сотрудником, проверю, что каждый видит только своё.
- Убедюсь, что проект собирается без ошибок.

## Технически
- Аккаунты — через Auth Admin API (`email_confirm: true`), роли в `user_roles` (`admin` / `staff`); старый пользователь удаляется, профиль и роль уходят каскадом.
- Миграция: политики чтения `orders`/`order_items` и обновления `orders` расширяются на `staff`; товары, удаление заявок и роли остаются только у `admin`.
- `src/lib/orders.functions.ts`: `crypto.randomUUID()` для `orders.id`, вставка без `.select().single()`.
- `getMyAccess` возвращает роль, панель скрывает недоступные разделы.
